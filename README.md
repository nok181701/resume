#### ① 電話番号LP開発

- 期間: 2025/10〜現在
- 職種: フロントエンドエンジニア
- 役割: リーダー
- 体制・組織規模: 開発課 2 人
- 目的:
  - 営業担当者が求職者に電話をかけても出てもらえないケースがあり、ユーザーが着信番号を検索する動きが一定数存在。しかし現状ではその検索時に表示されるのは電話帳ナビなどの外部サイトであり、自社との接点を損失。また LP を作成しても 1 ページ単体では SEO 的に評価されづらく、流入に繋がらないのが課題。
  - そのため、着信番号を検索したユーザーが自社の電話番号 LP に自然に流入できる構造を開発。
- 担当業務:
  - ユーザーが営業担当者の電話番号を検索したときに専用 LP がヒットするように開発
  - 事業部側と連携し電話番号 LP の雛形を設計・実装を担当
  - サイトマップ・構造化データの実装
  - 営業担当者が CMS 上で作成したプロフィール記事を、CI のタイミングで SSG ビルドし、S3 + CloudFront で配信する構成
  - 営業担当者が好きなタイミングで記事を公開したいため、Slack 経由でのデプロイを SRE チームと連携して実現
  - 他職種サイトへの横展開
- 結果: POS 職種で 2025/10 から施策実施中（月間架電数 約 13,110 件）
  - 番号検索率: 平均 5.1%（671 件/13,110 架電）
  - 検索結果からの LP CTR: 平均 10.9%
  - LP 内スクロール 90%到達率: 約 14%
  - 連絡ボタンクリック（接触アクション）: 月平均 11 件、CVR 平均 0.09%
- 利用技術: Next.js(v13), Next.js(v14), TypeScript, microCMS

#### ⑤ 各職種LP登録サイトのリプレイス対応

- 期間: 2024/10〜2025/4
- 職種: フロントエンドエンジニア
- 役割: メンバー
- 体制・組織規模: 開発課 25 人
- 担当業務:
  - 他職種展開の前に、スモールスケールで特定の職種を先行して担当
  - バックエンドチームと連携し、既存システム（CakePHP）を読み取り、現行仕様を確認
  - Next.js の静的エクスポート機能を使い、S3 に資材を置き CloudFront で配信管理が実現可能かどうか SRE チームと連携して作業
  - 事業部側と連携しながら GTM の発火確認、外部の AB テストツールが使用できるかどうかの確認
  - 他職種のコードレビュー
- 課題:
  - Next.js の静的エクスポート（next export）はデフォルトで `/out` フォルダに HTML を出力するため、そのまま S3 + CloudFront にデプロイすると「ドメイン/out/...」という階層でしか表示されない問題があった
  - CI（yml ファイル）に、`/out` 配下の HTML ファイルをルート直下へ mv するステップを追加し、ドメイン直下で正しく表示されるように解決
- 利用技術: Next.js(v14), TypeScript, CakePHP（既存システム）
